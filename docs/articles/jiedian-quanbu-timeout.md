# 节点全部超时怎么办？Clash / Shadowrocket / v2rayN / NekoBox 全部 timeout 排查

> 客户端里所有节点都显示 timeout、failed 或 error，一个都连不上。本文按卡点分层排查：先分清是本机还是机场，再处理「流量能用 Wi-Fi 不能用」「官网状态正常我这里却全超时」「换过网络改过 DNS 仍然超时」，附 Clash Verge、Shadowrocket、v2rayN、NekoBox 各自的专属检查项。
>
> 发布 2026-08-14｜原文：[https://jcyyds.com/blog/jiedian-quanbu-timeout/](https://jcyyds.com/blog/jiedian-quanbu-timeout/)

---

打开客户端，测速一按，**所有节点整整齐齐全是 `timeout`**——不是某一个慢，是一个都连不上。有的客户端显示 `failed`，有的显示 `error`，Clash Verge 上是一片红。

这篇按**真实用户卡在哪一步**来分层。如果你只是刚遇到问题，从第一节开始；如果你已经换过网络、校准过时间、重导过订阅还是不行，直接跳到第四节——前面那些对你没用了。

<span id="quick" class="block scroll-mt-24"></span>

> **三十秒先做这一步**：把手机 Wi-Fi 关掉，用**移动数据**连一次。
> 恢复了 → 问题在你当前的网络环境（第二节）；
> 还是全超时 → 问题在订阅或机场侧（第三、四节）。
> 这一步能把可能性砍掉一半，比任何其他操作都值得先做。

<span id="triage" class="block scroll-mt-24"></span>

## 一、先判断是本机还是机场

「全部超时」这个现象本身不指向任何具体原因——它只说明**没有一个节点握手成功**。而握手要经过：你的设备 → 本地网络 → 运营商 → 节点服务器。任何一环断了，表现都一样。

所以第一件事是定位在哪一环。

### 按分辨力排序的五步

顺序是有讲究的，分辨力最高的排在前面：

1. **换一个完全不同的网络**（Wi-Fi ↔ 移动数据，或换一个 Wi-Fi）。这一步分辨力最高。
2. **换一台设备**，同一份订阅在另一台机器上导入试试。
3. **手动更新一次订阅**，看节点列表有没有变化、数量对不对。
4. **确认系统时间准确**（偏差超过几分钟会让部分协议握手失败）。
5. **关掉代理，看能不能正常打开国内网站**——排除本机网络本身就断了。

### 五步做完，结果分三种

| 结果 | 指向 |
| --- | --- |
| 换网络后能用 | 当前网络环境的问题 → 第二节 |
| 换设备也全超时、订阅能刷新 | 订阅内容或机场侧 → 第三、四节 |
| 订阅刷新失败 / 节点列表是空的 | 订阅地址或机场入口的问题，先看[机场入口可达性监测](https://jcyyds.com/status/)那家今天通不通 |

如果这几步你已经全做完了还是不行，那你的情况在第四节，不在这里。

<span id="wifi" class="block scroll-mt-24"></span>

## 二、手机流量能用，Wi-Fi 不能用

这是最容易被误判成「机场坏了」的一种，因为在同一台手机上同一个客户端表现完全不同。

**它只能说明一件事：问题跟你当前这个 Wi-Fi 网络环境高度相关。**

### 候选原因有六类，DNS 只是其中之一

不能直接推出是哪一项——下面这些的表现完全一样：

- **DNS**：路由器或运营商下发的 DNS 解析不出节点域名
- **IPv6**：Wi-Fi 下拿到了 IPv6 地址，客户端优先走 v6 而节点只有 v4
- **路由器**：某些路由器的「安全防护」「广告过滤」「游戏加速」会拦截代理流量
- **ISP 过滤**：部分地区的宽带对特定端口或协议有干预，移动数据网络没有
- **防火墙**：公司/学校/酒店网络的出网限制
- **MTU**：链路 MTU 偏小导致握手包被丢，这种往往表现为「连上了但立刻断」

### 怎么逐个排除（按代价从低到高）

1. **换个 Wi-Fi**（邻居的、公司的）。如果换一个 Wi-Fi 就好了 → 是那个路由器/宽带的问题，不是机场。
2. **手机上关掉 Wi-Fi 的私有地址/随机 MAC**，再重连。
3. **在路由器里关掉 IPv6**，或在客户端里把 IPv6 关掉，重测。
4. **把路由器的安全防护/DNS 过滤类功能全关**，重测。
5. **改 DNS**（见第五节）——注意这只是候选之一，不是万能药。

排到第几步好了，第几步就是原因。**跳过前面直接改 DNS 是最常见的弯路**，因为改完没好会让人误以为「DNS 也试过了，肯定是机场问题」，而实际上根本没测到点上。

<span id="status-green" class="block scroll-mt-24"></span>

## 三、官网节点状态正常，但我这里全部超时

这是顾客问得最多、也最容易产生不信任的一条：「你们官网写着节点正常，为什么我这边一个都连不上？」

**因为状态页和你测的不是同一条链路。**

```
状态页测的：   监测服务器 ──────────────→ 机场节点
你实际走的：   你的设备 → 本地网络 → 运营商 → 机场节点
```

状态页(包括本站的[机场入口可达性每日监测](https://jcyyds.com/status/))通常是从固定的监测点发起探测，**验证的是「节点服务器还活着、还在响应」**。而你这一端要多走本地网络、DNS、运营商这几段——这几段状态页一段都测不到。

所以这两句话可以同时成立，并不矛盾：

- **状态页显示正常** = 节点服务器本身没死
- **你全部超时** = 从你的位置到那台服务器的路上断了

反过来也一样：状态页显示不可达，也不一定代表你就用不了(可能只是监测点到它的那条路不通)。

### 一个例外：状态页显示绿色，但所有人都连不上

**如果节点域名的 DNS 解析出了问题**(比如 CNAME 指向了一个不存在的地址)，那所有人都连不上，而只测「服务器 IP 是否响应」的状态页仍然可能显示绿色。这时候状态页不是在撒谎，是它测的那一项确实没坏——坏的是把域名翻译成 IP 这一步。判断方法：在电脑上 `nslookup 节点域名`，如果返回 `NXDOMAIN` 或解析不出地址，那就是这种情况，**顾客侧无解，只能等机场修**。

<span id="deep" class="block scroll-mt-24"></span>

## 四、已经换网络 / 校准时间 / 重导订阅，还是超时

到这一步说明基础清单对你无效了。往下的检查更细，按顺序做：

### ① 看订阅拉下来的节点数量对不对
在客户端里打开订阅详情，看节点条数。如果比你买的套餐应有的少很多、或者只有一两个测试节点，说明**订阅内容本身就不对**——可能是订阅链接过期、被重置、或者你复制的时候漏了结尾字符。重新从官网后台复制一次完整链接。

### ② 确认订阅链接是完整的
中文输入法在复制长链接时容易吞掉结尾字符，这是真实高频的原因。粘贴后对一下最后几位。详细步骤见[Clash 订阅导入完整教程](clash订阅导入教程-机场订阅怎么用.md)。

### ③ 换一种协议试
如果客户端里能看到节点的协议类型，优先试不同协议的节点（比如 Hysteria2 全超时就试 Trojan/VLESS）。某些协议对丢包和 QoS 更敏感，在某些网络下会整类失效，而另一类协议正常。**只测同一种协议的十个节点，等于只测了一次。**

### ④ 关掉所有其他代理软件和浏览器代理插件
两层代理互相打架是常见成因，表现正好是「全部节点都连不上」。

### ⑤ 检查客户端的 TUN / 系统代理模式
从系统代理模式切成 TUN 模式（或反过来）再测一次。有些环境下系统代理写不进去（Windows 上常见的「系统代理开启失败，已断开连接」就是这一类），此时节点其实是通的，只是流量没走进代理。

### ⑥ 换一个客户端
用另一个完全不同的客户端导入同一份订阅。这一步的意义是**把客户端本身摘出去**——如果换了客户端就好了，那就是原来那个客户端的配置或版本问题，跟机场无关。

<span id="dns" class="block scroll-mt-24"></span>

## 五、已经改了 DNS，还是超时

改 DNS 只解决一种情况：**节点域名解析不出来**。如果不是这个原因，改再多次也没用。

### 先确认到底是不是 DNS 问题，别猜

```
Windows:  nslookup 节点域名
macOS:    dig 节点域名
```

- 返回了正常 IP → **不是 DNS 问题**，别在这上面继续花时间，回第四节
- 返回 `NXDOMAIN` / 无法解析 → 确实是解析问题
- 用公共 DNS（如 `1.1.1.1`）能解析、用运营商 DNS 解析不出 → 是运营商 DNS 的污染或缓存

### 确认是解析问题之后，两个容易漏的点

- **客户端内部的 DNS 配置会覆盖系统 DNS。** 你在系统里改了 DNS，但 Clash 配置文件里 `dns:` 段写死了别的服务器，实际生效的是配置文件里那个。要改就改配置里的。
- **配置里的 `proxy-server-nameserver` 指向了一个已经失效的地址**，会导致节点域名根本解析不出来。这一项经常被从旧配置里继承下来，自己不会报错，只表现为全部超时。

还有一种彻底无解的情况：**节点域名在机场那一侧就配错了**（域名指向一个不存在的地址）。这时候你换任何 DNS 都解析不出来，因为源头就没有正确记录。判断方法同上——多个公共 DNS 都返回 `NXDOMAIN`，那就是机场侧的事，等它修。

<span id="clash" class="block scroll-mt-24"></span>

## 六、Clash Verge 特有检查

- **内核选择**：如果你改过内核或用了「覆写」功能，把覆写关掉再测。覆写脚本写错会让所有节点失效，而界面上不会有任何报错。
- **配置文件里的 `dns:` 段**：见第五节，客户端 DNS 覆盖系统 DNS。
- **`proxy-server-nameserver` 里的地址是否还有效**——旧配置继承过来的死地址是真实成因。
- **测速用的测试地址**：默认的延迟测试地址如果本身被墙或改过，会让所有节点都显示超时，而节点其实是好的。换一个测试 URL 再测。
- **Service 模式 / TUN 模式**是否正常启动，Windows 上服务没起来会全线失败。

<span id="shadowrocket" class="block scroll-mt-24"></span>

## 七、Shadowrocket（小火箭）特有检查

- **扫码导入提示异常**：优先改用「从 URL 下载配置」的方式导入，二维码在压缩后容易解析出错。
- **iOS 的「私人 WLAN 地址」**：设置 → Wi-Fi → 当前网络 → 关掉私有地址，重连后重测。
- **低数据模式 / 低电量模式**会限制后台连接，建议排查期间都关掉。
- **VPN 配置描述文件冲突**：设置里如果存在多个 VPN 描述文件，删掉不用的那些。
- **同一份订阅在电脑上能用、小火箭全超时** → 先按上面四条排，通常不是订阅的问题。

<span id="v2rayn" class="block scroll-mt-24"></span>

## 八、v2rayN 特有检查

- **看日志，不要只看测速结果。** v2rayN 的日志窗口会直接给出失败原因，比「timeout」这三个字信息量大得多。
- **系统代理开启失败**：这是 Windows 上的高频报错，说明代理没写进系统设置，此时节点通不通根本没测到。以管理员身份运行、或改用 TUN 模式。
- **核心版本**：Xray 核心太旧会不支持较新的协议（比如 Hysteria2），表现为该协议的节点全部失败。
- **测试地址**：同 Clash，默认测试地址不可达会让所有节点都显示超时。
- **PAC 模式下的 `pac.txt`** 如果损坏，会导致分流全错。切成全局模式测一次即可排除。

<span id="nekobox" class="block scroll-mt-24"></span>

## 九、NekoBox 特有检查

- **内核未下载完整**：NekoBox 需要下载对应内核，下载不全时所有节点都会失败。到设置里重新下载一次。
- **VPN 模式 vs 系统代理模式**：Android 上优先用 VPN 模式测。
- **省电优化**：把 NekoBox 加入电池优化白名单，后台被杀会表现为连接反复中断。
- **分应用代理**：如果开了分应用代理而测试用的应用不在名单里，会看起来「全部不通」。

<span id="airline-side" class="block scroll-mt-24"></span>

## 什么时候才能判定是机场侧的问题

这是最容易下结论太快的地方。**单独一条都不足以判定**，需要同时满足：

1. **多个客户端都复现**（换了客户端仍然全超时）
2. **多个网络环境都复现**（Wi-Fi、移动数据、另一个 Wi-Fi 都不行）
3. **订阅刷新正常**（能拉到节点列表，数量也对）
4. **该机场的服务状态确实异常**（官方公告、或者节点域名解析不出来）

四条都成立，机场侧故障的概率才明显提高。只满足前一两条的时候，更可能还是本地环境的问题。

如果确认是机场侧，而且**连续多天没有恢复、官方也不给明确说法**，那才到了考虑换一家的时候。判断一家值不值得继续等，可以对照[如何判断机场会不会跑路](ruhe-panduan-jichang-paolu.md)里的几个信号；已经确认停运的，见[已跑路机场名单](https://jcyyds.com/scam/)。

要换的话，先看[机场推荐排行榜](https://jcyyds.com/rank/)——榜单前几位是本站编辑推荐位、掺入了合作关系，想看完全不受推荐影响的排序，去[纯价格表](https://jcyyds.com/rank/#price)。稳定性优先的话，走内网专线的那一档抗故障能力更强，区别见[IPLC、IEPL、中转与直连的差别](iplc-iepl-zhongzhuan-zhilian.md)。
