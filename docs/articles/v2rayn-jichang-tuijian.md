v2rayN（Windows）和 v2rayNG（安卓）是同一个作者维护的开源项目，免费、体积小、协议支持全。它们的共同点也很明确：**只是客户端，一个节点都不提供**。

所以搜「v2rayN 机场推荐」的人真正要解决的是：*这个客户端对机场订阅有什么特殊要求，选的时候该看什么*。

## 先搞清 v2rayN 和 Clash 的定位差别

很多人纠结该用哪个，其实取舍很清楚。

**v2rayN 更接近「配置的直接暴露」。** 它把每个节点的参数摊开给你，改传输协议、改 TLS 设置、加自定义出站规则都很直接。适合想弄清底层在发生什么的人。

**Clash 系（Verge、Mihomo）的强项是规则分流。** 它的配置文件天然就是一套规则引擎，做分应用、分域名、分地区的策略比 v2rayN 顺手得多。日常使用的图形化程度也更高，导入流程见 [Clash 导入订阅教程](clash订阅导入教程-机场订阅怎么用.md)。

**结论**：只要能连、想少折腾，用 Clash 系；想手动调参数、排查具体某个节点的问题，v2rayN 更合适。两个都装也完全没问题，但**不要同时开启**——两个客户端抢系统代理设置，只会互相打架。

## 选机场时必须确认的三件事

### 一、订阅格式对不对

机场的订阅链接通常有多种格式：Clash 用的 YAML、v2ray 系用的 Base64 编码节点列表、Surge 用的 conf。**把 Clash 那条订阅塞进 v2rayN，多半解析不出来。**

选机场时看一眼用户中心有没有单独提供 v2rayN / v2rayNG 的订阅入口。绝大多数正规机场都有，但一些主打 Clash 的新机场会漏掉这一项。导入步骤见[订阅导入教程](https://jcyyds.com/guides/)。

### 二、协议支持范围

v2rayN 内核基于 Xray/v2ray-core，对 VMess、VLESS、Trojan、Shadowsocks 支持完整，新版本也支持 Hysteria2、TUIC。

需要注意的是**机场端的协议策略**：有些机场为了降低被识别的概率，主推自研或小众协议，这类节点在 v2rayN 里可能需要额外配置甚至根本用不了。判断方法很简单——看机场文档里列没列出 v2rayN 的配置教程。列了就基本没问题。

### 三、节点命名规范

这一条听起来琐碎，但用久了很影响体验。v2rayN 的节点列表是纯文本表格，如果机场的节点名把地区、倍率、线路类型都标清楚（比如「香港 IEPL 1x」），你一眼就能挑；如果全是「节点 001」「节点 002」，你只能靠试。

倍率标注尤其重要，不然流量会掉得莫名其妙，具体见[流量倍率怎么算](liuliang-beilv-taocan.md)。

## 系统代理还是 TUN 模式

这是 Windows 端最常见的困惑。

**系统代理模式**：客户端修改 Windows 的全局代理设置，走 HTTP/SOCKS。优点是不需要管理员权限、不装虚拟网卡、稳定。缺点是**只有遵守系统代理设置的程序才会被代理**——浏览器一般没问题，但很多游戏、部分桌面软件、命令行工具会直接绕过。

**TUN 模式**：创建一个虚拟网卡，接管全部流量。优点是所有程序都被覆盖，没有漏网之鱼。缺点是需要管理员权限，且和某些安全软件、虚拟机网络会冲突。

**建议**：默认用系统代理，只在发现某个程序绕过代理时才切 TUN。不要一上来就全局 TUN——出问题时排查范围会大得多。

## 安卓端的 v2rayNG

安卓端因为系统本身提供 VpnService，不存在系统代理和 TUN 的选择问题，v2rayNG 一律走 VPN 接口，所有 App 的流量都会被接管。

但有两个安卓特有的坑：

- **省电策略会杀后台**。国产 ROM 尤其激进，必须在系统设置里给 v2rayNG 单独放开后台运行和自启动，否则锁屏一会儿就断。
- **分应用代理值得配。** v2rayNG 支持按 App 选择走不走代理。把国内应用排除掉，既省流量又省电。

移动网络频繁切换的场景下，节点稳定性的重要性会被放大。iOS 端有类似的考量，见 [Shadowrocket 机场推荐](shadowrocket-jichang-tuijian.md)。

## 出问题时先分清是谁的锅

| 现象 | 通常原因 |
| --- | --- |
| 导入订阅后节点为空 | 订阅格式不对，换 v2ray 专用链接 |
| 全部节点延迟检测超时 | 订阅过期、流量用尽，或本地网络问题 |
| 能连上但网页打不开 | 系统代理未生效，或规则把域名放行了 |
| 部分程序不走代理 | 该程序不遵守系统代理，需要 TUN |
| 晚上八点后极慢 | 机场超售，见[晚高峰卡怎么办](wangaofeng-ka-zenme-ban.md) |

**排查顺序永远是：先换节点，再换客户端，最后才怀疑机场。** 很多人第一步就下单换机场，钱花了问题还在。更多报错见[机场报错排查](https://jcyyds.com/troubleshoot/)。

## 电脑端选机场的一个实际建议

桌面端和手机端有个真实差别：**电脑上的流量消耗通常大得多**。大文件下载、开发环境拉依赖、云盘同步、Steam 更新，一不留神几十 GB 就没了。

所以电脑为主的用户，比手机用户更该关注**流量额度而不是节点数量**。同样的钱，选一个 200GB 的套餐往往比选一个节点更多但只有 100GB 的划算。如果你的用量波动很大，[按量计费类机场](https://jcyyds.com/topics/cheap/)反而更合适。
